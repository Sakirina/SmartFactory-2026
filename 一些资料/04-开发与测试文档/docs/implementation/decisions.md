# 方案调整记录

本轮以 2026 年 9 月 20 日确认的完整交付计划为实施依据，保留原基线文件供追踪；部署、存储和材料中的陈述以本轮方案及实际证据为准。

| 事项 | 本轮方案与依据 | 对应基线 |
|---|---|---|
| 服务组织 | 采用 ThingsBoard CE、Edge 和 Go 扩展集中承担六类业务职责，配置中心独立运行；来源为完整交付计划的服务组织选择 | 平台 FR-GW、FR-DP、FR-OC、FR-AU、FR-AM、FR-IAM |
| 客户与租户 | 每个客户独立部署，每套实例使用一个业务租户；ThingsBoard 内部保留其租户字段，来源为计划中的客户部署选择 | 网关 FR-GW-101、102 |
| 数据契约 | DataTransfer 继续使用 DeviceMessage，边缘适配器保存标准业务观测并同步到云端；消息、命令与实体版本身份贯穿协议、业务和审计，来源为计划中的公共契约 | 平台 FR-GW-003、004；网关 FR-GW-112、113 |
| 提交确认 | 事件、回执、配置与规则保存后确认，持续观测采用接收确认及明确缺口；本轮采用完整的两类确认机制 | 网关 FR-GW-114 至 118 |
| 失败投递 | 配置与持久事件沿用原 ID 等待恢复，失败任务保存原因并递增等待；即时控制按节点状态和启动期限拒绝。运行状态显示积压及失败，来源为计划中的重连续投与即时控制要求 | 网关 FR-GW-117、121、130 |
| 原始观测 | 默认完整保存 30 天；最近 24 小时保持热数据，其余采用可恢复全部字段和精度的压缩归档，来源为本轮存储方向的追加确认 | 平台 FR-DP-003、030、NFR-C-020 |
| 测试写入 | 大量功能、查询和性能测试采用内存数据库及有容量限制的 tmpfs；持久提交与恢复采用有明确规模的磁盘测试，来源为减少无意义高磁盘 I/O 的追加要求 | A04、A06、A08、A12、A18 |
| 原生服务内存 | 本机原生云平台上限 4GiB、单个 Edge 上限 2GiB，启动服务前检查主机可用资源并保留至少 2GiB；来源为本轮资源配额追加要求 | A01、A05 |
| 国产化范围 | 目标为完整 UOS Server V20 x86_64、PostgreSQL 和标准 mTLS；达梦与国密专项适配列为后续扩展，来源为完整交付计划中的国产化选择 | 平台 NFR-C-021、040；网关 NFR-GW-04 |
| AI 范围 | 页面助手和 MCP 使用统一目录与三类草稿，人工发布和执行；来源为完整交付计划的前端与 AI 要求 | 平台 FR-DP-004、FR-OC-013、FR-AI-001 至 004 |

进程插件通过 SDK 实现外部字段到平台契约的转换，插件配置与程序参数具有各自的版本记录。采集字段的字节顺序、位字段、单位与反向编码保存在设备采集配置中，组织插件返回统一组织契约；维护入口分别位于设备配置、同步插件和配置中心页面。

截止当前阶段，UOS 虚拟机尚未创建，完整目标系统安装、持续断云与实际存储测量保留在 [验收追踪表](requirements.md) 中，相关脚本通过已有配置生成和短期功能记录持续补充证据。
