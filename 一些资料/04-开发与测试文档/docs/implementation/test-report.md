## 故障与权限覆盖

Go 回归覆盖配置和消息同版本冲突、数据库提交失败、原 ID 重投、命令启动过期、非幂等结果待核对、确认人数不足、会签有效期、组织关系变化、权限撤销、指定本地安全员二次认证，以及每个设备步骤前的物理联锁复核。

采集转换测试为每类协议提供至少 1000 组数据，校验精确整数、布尔、浮点容差、单位、时间和质量；OPC-UA 另行验证证书、加密、方法调用和订阅恢复，独立采集插件与组织插件均覆盖进程异常隔离。

数据回归覆盖 GOOD 过滤、同一时间的不同事件、历史规则及资产版本、乱序与补传、72 小时历史计数恢复、实时后续处理、告警确认保留、修订前后值、聚合与局部保留期清理。归档测试覆盖完整字段恢复、热数据和归档修订合并、事务失败回滚、摘要损坏、块局部到期、备份恢复与过期分区再次收到补传。

AI/MCP 测试使用固定模型模拟器，验证三类定义的创建、修改、校验、解释和差异查看；直接发布、设备控制、凭据读取和资源越权均由服务端权限检查拒绝，正式版本摘要保持一致。

## 材料与故障修复验证

[116.4 秒演示](../../deliverables/SmartFactory五场景演示.mp4)记录实际设备状态与页面，包含 13 项自动断言；录制期间 ThingsBoard CE、Edge 和 Kafka 均在线，[录制结果](../evidence/demo-video.json)与[服务状态](../evidence/native-recording-services.json)保留对应时间。产品介绍的 7 页文档、14 页 PPT 与六个视频时间点均完成[视觉检查](../evidence/materials-visual-qa.json)。

干净部署完成了[云端与 Edge 的原生规则回调](../evidence/native-clean-deployment.json)。录制结束后，15:30:44 的 Docker 虚拟机全局内存不足触发内核终止 CE Java 进程，容器随后自动重启；本机 Docker 虚拟机分配 8GiB 内存，原生 CE 与 Edge 的容器上限分别为 4GiB 和 2GiB。[内核与重启记录](../evidence/native-post-recording-resource-event.json)保存了此事件，恢复后[云端与 Edge 的回调复验](../evidence/native-after-vm-resource-recovery.json)均通过，测试容器随后清理。持续运行与内存预算仍纳入 UOS 目标环境验收。

现场故障测试发现过执行权竞争被误判为协调服务失联的情况，修复后将第二阶段 CAS 冲突归为已有执行者持权，并重新完成 100 轮。原生服务不可达时，投递任务采用递增等待，实时策略使用独立队列；[实际故障恢复](../evidence/native-outage-control-recovery.json)记录温度变化后风机动作延迟，原生服务在线时的湿度动作见[运行记录](../evidence/realtime-recovery-native.json)。
