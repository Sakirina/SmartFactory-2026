发布协调工程师任务说明

本任务负责 E5-01、E5-03 和 E5-04 的程序、规则与配置发布模型、协调器及批次行为。配置与节点身份工程师负责受认证身份约束的配置分发和回执，发布界面工程师负责页面，构建交付工程师负责最终包及部署入口。实施前读取前四阶段接口、兼容清单、编号迁移和后台任务约定，明确实际可应用的程序、规则及配置对象。

完整发布对象保存各组件的版本、内容摘要、依赖、目标能力和兼容要求。创建与准备阶段校验全部内容及依赖闭环，同一发布身份具有固定内容；缺失依赖、循环、不兼容程序与规则格式、数据库版本不符或摘要不符时返回对应对象和原因。构建产物清单与发布对象能按摘要交叉核对，程序、规则和配置分别引用实际被应用的内容。

发布协调器保存目标节点的期望、准备、应用、运行及失败状态，通过幂等操作推进到声明目标。节点报告带认证主体、版本、摘要和运行实例，过期或重复报告按持久状态处理。协调器与节点重新启动后根据已有记录继续执行，节点已经应用的相同内容能够被识别；实际运行状态应来自运行进程及生效配置和规则的可核对报告。

分批发布按明确节点集合和依赖次序推进，每批保存进入条件、结果和人工处理事项。离线节点进入等待，恢复后检查当前期望版本及兼容性；失败批次按规定停止后续推进，用户能够查看具体失败节点和组件。退回使用明确旧发布对象并检查程序、数据库迁移、规则格式和配置的兼容要求，已超出可退回条件时提供可执行的恢复流程。模板版本演进沿用第四阶段实例身份与绑定关系，显示所生成发布对象及影响范围。

验证流程如下：

1. 验证发布清单依赖、内容摘要、身份重复、版本和兼容条件，覆盖被修改的程序包、规则和配置以及缺失组件
2. 用隔离的实际云端与边缘进程完成准备、应用和运行报告，核对程序构建信息、生效规则及配置版本，验证重复协调和进程重新启动
3. 对两个以上目标节点完成分批推进，注入离线、应用失败和错误报告，核对批次停止、等待、恢复及持久状态
4. 完成支持的旧发布退回，验证不兼容退回的拒绝与恢复说明；结合构建交付工程师处理 Edge 正常停止和保留数据再次启动
5. 提供 `release-frontend-contract.md` 与 `.local/evolution/release-coordination-verified.json`，保存实际产物、节点状态、故障步骤、审计及受测源摘要

文件归属包括发布应用用例、协调器、发布与节点运行模型、相关API和测试。与节点身份工程师先约定报告格式、身份来源和下一迁移编号，再修改共享模型、`app.go`、任务登记、部署配置和生成契约；实际程序部署使用本轮隔离目录与进程。

第四阶段业务流程专家为设备参数与模板能力核对补充带版本的`connector_configuration`及相关配置应用用例，配置依据包含来源、版本与下发确认状态。开始本任务时读取该专家最终契约和验证报告，复用已有正式设备与连接器配置记录来实现节点身份校验、分发、生效确认及批次协调；新节点状态或凭据引用字段继续与相应记录关联。模板实例化读取固定配置版本并生成草稿，配置下发由明确的配置操作触发。

P4-B02涉及配置版本与密钥载荷的对应关系：每个配置版本使用固定密钥引用，worker验证载荷身份与版本后下发；延迟旧任务、并发保存新版及新版先应用均需要保持正确的版本关系。第五阶段发布与退回复用该版本记录，密钥载荷保存及读取沿所属节点授权执行。
