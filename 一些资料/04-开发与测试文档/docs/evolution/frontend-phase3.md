# 控制执行与历史分析页面

第三阶段的云端控制台和现场工作台已经提供控制执行详情、人工核对与恢复、历史回放、版本比较、影子候选及节点解释。页面使用 `contracts/1.0/openapi.json` 生成的类型和统一客户端，时间、版本、观测数值与导出继续采用精确整数处理。机器可读验证报告位于 `.local/evolution/frontend-phase3-verified.json`，截图、请求正文、服务端状态和产物摘要位于 `.local/evolution/frontend-phase3/`。

控制页面通过“审批与执行”查看执行列表，也可以填写执行身份或使用 `#executions?execution=<身份>` 打开指定详情。详情同时展示采用的预案版本、会签、判断条件、正常与降级步骤、设备命令及反馈、人工请求、原命令证据和关联时间线。工程师可以为已发布预案建立即时控制请求，工程师、领导与现场安全员的会签按钮按当前登录角色、执行状态和入口条件显示，正式下发提交当前执行版本。

人工取消、核对和恢复严格采用服务端 `allowed_actions`；禁止操作时，页面保留具体原因。云端请求版本和目标边缘来源版本分别显示，提交包含人工理由、操作身份和两个版本。HTTP 202 后提示“等待边缘处理”，收到开始回执时提示已经开始处理，收到最终回执后根据当前执行结果展示完成、取消或错误。人工请求的受理状态与设备执行状态分别保留，详情中的原命令身份、请求时间、开始时间和完成时间用于核对处理过程。

处理结果未知的命令时，操作流程如下。

1. 打开执行详情，查看当前原命令、设备步骤、来源版本和允许操作，填写人工理由后提交“核对原命令结果”
2. 在“人工请求与回执”查看操作身份和处理状态；云端处于等待状态时继续查看回执，原请求需要再次提交时使用保留的同一操作内容
3. 在“原命令核对证据”核对命令身份、设备、内容摘要、反馈来源、可信标记和观测、采集时间，并查看“关联时间线”中的设备反馈
4. 服务端返回允许恢复后，提交“恢复剩余步骤”，核对执行结果与剩余步骤的实际反馈

取消停止尚未执行的步骤，已经发送的命令继续保留身份和迟到反馈。取消后详情根据服务端状态说明仍待核对的原动作，反馈到达后继续展示原命令的证据和时间线。

历史分析入口为“历史分析”，指定运行可以使用 `#history?run=<身份>`。创建回放时选择规则、时间范围、设备和字段；使用保留观测或填写显式观测数组，随后选择事件时间或提供顺序。历史数组留空时由服务端读取所需历史，填写 `[]` 时采用空历史。高级参数可以提供时钟、初始状态与资产版本，页面提交前校验字段和精确整数。

回放按照观测时间采用当时已发布的规则和资产版本，逐点表显示此次回放结果。版本比较指定两个已发布版本，共用输入、历史、初始状态、排序与时钟，表格显示两侧计划、数值、质量和差异。影子运行根据实际正式求值来源展示候选与正式结果比较，缺少正式结果时显示“暂无对应正式求值”。缺少比较数据的运行显示尚未取得比较结果。

运行详情显示计算进度、已提交游标、关联任务、采用的定义和资产版本、快照身份及摘要。完整快照按需读取，入口快照 `captured_snapshot_id` 与解析前序状态后采用的 `snapshot_id` 分别保留。逐点结果按服务端游标分页，节点解释展示输入身份、数值来源、节点输出、前后状态、路径、错误及动作意图。当前页结果与完整快照可以分别导出 JSON，超过 JavaScript 安全整数范围的数值继续按整数保存。

影子候选的新增、重新启用和停止提交当前管理版本，详情同时显示 epoch、已采集代次和已完成代次。下一代运行等待前序时，计算状态显示 `waiting_parent`，后台任务仍显示实际队列状态；两者可以在同一运行与任务身份下核对。计算失败保留快照、错误和游标，重试继续使用同一任务、River 作业和运行身份。

历史页面的操作流程如下。

1. 建立回放或版本比较，核对返回的运行身份、输入范围、排序和时钟
2. 打开运行详情，按需取得快照，查看逐点数值、采用版本及节点解释，并导出当前页或完整快照
3. 启用影子候选，查看候选代次和正式比较来源；需要停止或重新启用时，核对当前管理版本后提交
4. 运行失败或等待前序时，打开关联后台任务查看实际队列状态、失败原因和允许操作，按当前版本提交重试或取消

服务端每份运行的预算为 10000 个输入、40000 条历史、40000 个资产版本与 32 MiB 快照。空保留范围、超出预算和请求字段错误在创建窗口显示服务端原因，并保留已填写内容。403 或 409 后页面刷新对象及当前身份，版本冲突需要操作者查看新状态后再次提交；撤销管理角色后关闭管理窗口并清除旧成功提示，撤销读取资源后清除失去许可的详情，身份失效后清除会话并返回登录页。

验证覆盖实际云端与现场应用的离线人工请求、只读原命令核对、剩余步骤恢复、取消和迟到反馈，也覆盖回放、显式两版本比较、影子启停、过期管理版本、失败任务重试、等待前序任务取消、角色与资源撤销、身份停用、精确整数和大屏入口。历史操作前后，正式文档、观测、最新值、汇总、设备动作日志和引擎检查点的六组摘要保持一致；查询条件随验证记录保存。

三轮前端构建保留各自的源码摘要和产物。第一轮控制核对、恢复使用原 v2 双应用；第二轮修正待处理提示和结果比较含义，并在原 v2 双应用完成取消与迟到反馈；第三轮修正候选窗口层级和撤权后的窗口清理，并使用 C05 修复后的双应用补验云端可信证据及反馈时间线。当前正式产物为 `main-CiVE3bj4.js`，20 项前端回归、TypeScript 6 兼容检查、正式类型生成一致性、TypeScript 7 检查与 Vite 生产构建均已通过。
