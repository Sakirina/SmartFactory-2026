查询、分页与增量订阅契约

本接口覆盖 `entities`、`alarms`、`executions` 和 `trend`，使用当前登录身份和资源授权。客户端通过 `POST /api/sf/v1/queries/{kind}` 读取页面，通过 `POST /api/sf/v1/queries/{kind}/events` 建立流式 HTTP 订阅，两者使用相同的 JSON 查询条件及 Authorization 请求头；订阅请求可携带 `Last-Event-ID` 续传。正式类型由 OpenAPI 导出，本说明随实现验证同步更新。

查询条件包含 `resource_ids`、`keys`、`definition_id`、`status`、`entity_kind`、`search`、`assignee_id`、`handling_status`、`active`、`acknowledged`、`from_ms`、`to_ms`、`resolution`、`limit` 和 `page_token`。各类型只应用适用的条件，趋势时间范围必须明确，`resolution` 为 `raw`、`minute`、`hour` 或 `day`。页面使用 `sort_ms` 降序、`id` 升序的完整排序；普通页面最多 500 行，趋势最多 2000 行。

每页包含 `items`、`snapshot_cursor`、`next_page_token`、`has_more`、`scope` 与 `metadata`。客户端继续读取时提交完全相同的查询条件及 `next_page_token`，后续页面读取同一个已提交快照；并发新增、修改和删除通过该快照之后的增量呈现。每个查询行具有 `kind`、`id`、`revision`、`version`、`sort_ms` 和 `data`。`version` 是业务自身的版本，`revision` 是该查询行最后一次投影更新的提交序号，以十进制字符串传输；比较修订使用 BigInt 或十进制字符串比较，完整游标和分页令牌作为不透明字符串保存。

告警 `data` 保留生命周期字段，并合并 `case_version`、`assignee_id`、`handling_status`、`acknowledged`、`handling_updated_ms`，并提供完整 `handling_case` 和可用的原生状态 `native`。原生生命周期变化和人工处置变化都产生新的查询行修订。执行查询行包含当前执行字段与 `evidence_count`，新增命令证据会推进 `revision`，客户端据此刷新已打开的执行详情。趋势行保留观测身份、精确数值、单位、质量、来源、设备时间、接收时间、资产版本、规则版本和修订，页面元数据提供该快照下的来源、修订说明及缺口。`quality_scope=page` 表示 `good`、`bad`、`uncertain` 和 `excluded` 按当前页面统计；`missing` 和 `completeness` 依据整个固定查询范围内的缺口计算，缺口只与查询范围部分相交时，`missing` 保持未知。

订阅表示查询排序后的前 `limit` 行，并持续维护这个窗口。初次连接发送 `snapshot`，其数据包含完整页面和可恢复游标；后续 `delta` 包含 `changes`、`cursor`、`has_more` 和当前元数据。每条变化提供 `operation`（`upsert` 或 `remove`）、`kind`、`id`、`revision`，`upsert` 同时包含完整查询行。新行进入窗口时，退出窗口的旧行收到 `remove`。服务端可将轮询间隔内的多次提交合并为一个窗口差异，同一次提交的可见变化在完整事件中发送；客户端应用完整事件后保存 SSE `id`，按资源身份及修订处理重复传递。恢复也比较旧游标窗口与当前窗口，期间已经产生又退出窗口的记录由最终窗口状态决定。

断线后，服务端依据签名游标重建此前窗口，再按照已提交日志恢复增量；进程重启后继续使用数据库中的日志和历史投影。游标超出保留范围、投影重建导致代际改变、查询条件改变或授权改变时，服务端发送 `reset` 并结束流。`reset` 包含 `reason`、`clear` 和 `retryable`；客户端在 `clear=true` 时清空当前查询缓存和详情，再按最新身份重新查询。会话过期或撤销同样清除缓存，重新认证后才能订阅。普通分页使用 `error`、`code`、`clear`、`retryable` 返回错误：`query_changed`、`authorization_changed`、`projection_rebuilt` 为 409，`cursor_expired` 为 410，`invalid_cursor` 为 400；预算错误 `budget_exceeded` 为 413。

同一服务进程共享提交日志轮询；共享窗口同时绑定规范化查询、用户、会话、委托状态及当前身份和授权修订；仅资源范围相同的不同用户或会话使用各自的窗口。订阅取消后释放订阅者，最后一个订阅者退出后停止轮询。待发送事件队列和流式写入均有预算；慢客户端收到 `slow_consumer` 重置，无法写出重置信息时关闭连接，客户端使用最后成功保存的游标重新建立连接。查询达到服务预算时返回 `budget_exceeded`，页面中的 `has_more` 明确表示仍有后续结果，趋势导出需要逐页取得完整范围。

投影更新与业务事实、提交日志处于同一数据库事务，提交水位在事务最终阶段分配。重建从当前文档、观测、归档、汇总、修订和缺口恢复投影，在一致事务中切换投影代际并推进水位；失败时原投影继续有效，成功后旧分页和订阅通过 `reset` 重新取得快照。重建使用与在线更新相同的派生观测版本规则，重复或较早修订不会覆盖较新的结果。

普通页面默认 100 行，资源筛选最多 256 项，趋势键筛选最多 128 项；趋势固定时间范围最多三年，来源、修订和缺口各最多 2000 条，超出时返回预算错误。服务端保留最近 4096 次查询提交，并由每分钟维护任务清理过期历史；单进程最多 128 个不同查询窗口和 256 个订阅者，每个订阅队列最多 32 个事件。共享提交轮询间隔为 250 毫秒，空闲连接每 15 秒发送注释心跳，单次写入与刷新期限为 3 秒，写入完成后解除该期限。

趋势的 `from_ms` 和 `to_ms` 在分页及续传期间保持固定。实时视图随展示时间范围前移时更新这两个值并建立新订阅，新条件取得新的快照。来源心跳过期时，即使业务提交序号保持不变，服务端仍发送带最新 `metadata` 的 `delta`；客户端每次处理事件都应用元数据，游标用于判断业务行的已提交位置。趋势续传的首个差异事件也包含当前来源状态。JSON 数值保留原始精度，客户端沿用 `precision.ts` 的精确解析与序列化函数处理页面和 SSE 数据。

重建通过有限批次读取当前事实，在线调用最长 30 秒并接受调用方提前取消。重建期间，PostgreSQL 读取继续看到原有已提交代际，其他业务事务可准备写入，其最终提交等待代际切换；SQLite 按现有单连接事务方式执行。取消或数据库错误会回滚本次重建，成功切换后排队的业务更新在新代际推进提交序号。专家验证记录保留取消、回滚、同时写入与解除阻塞后的实际用时。
