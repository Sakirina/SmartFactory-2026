第二阶段集成审查任务说明

独立审查工程师负责 E2-01 至 E2-12 的证据核对、跨模块回归和缺陷定位，同时复查第一阶段在第二阶段改动后的适用验收项。对应实现分别由存储与后台任务、规则计算、AI 协议和前端基础工程师负责；审查发现的功能缺陷交给对应负责人修复，主协调者确定文件归属及再验证安排。

首先读取 [逐项验收](acceptance.json)、[团队安排](team.json) 及各工程师最终验证报告，核对命令、退出状态、样本、实际版本和文件摘要。生成代码、契约与当前源码之间需要重新核对，早期二进制和截图仅用于说明当时的验证结果。每项判断必须具有可定位的证据，未执行、跳过、模拟端点、真实数据库及浏览器验证分别按实际范围记录。

审查流程如下：

1. 运行两个 Go 模块的适用全量测试、前端类型检查与生产构建、生成契约一致性和样本检查，记录全部失败、跳过及环境原因；并发与状态共享模块采用有针对性的 race 检查
2. 对 PostgreSQL 16 至 18 迁移、编号迁移及 River 使用方式检查数据与业务语义，包括任务同事务入队、回滚、崩溃恢复、调度预算和任务详情；核对独立对象并行、同对象竞争、迟提交日志与同步游标、审计链以及归档期间晚到数据的实际 PostgreSQL 测试，检查消息基础设施迁移报告及正式部署锁的一致性
3. 检查编译计划所有生产入口、计划身份与格式、摘要拒绝、旧消息补齐、启动诊断和运行时复用；用同一输入序列、时钟、初始状态与资产版本交叉核对实时、连续模拟和补算，并验证运行隔离、取消与资源预算
4. 用官方 MCP 客户端和既有客户端检查协议协商、权限、草稿调用与错误，检查旧实例模型配置 Schema 升级以及两个模型 API 的完整工具循环、精度、流式结束与异常处理
5. 使用实际页面完成连续模拟与任务详情流程，验证过期修订、失败任务操作、身份撤销、精确整数和三个页面入口；核对 Node、Vite 与 TypeScript 迁移的版本及锁文件
6. 将每个需求对应的通过、缺陷及剩余验证整理为 `.local/evolution/phase2-independent-review.json`，附命令日志与受测摘要；只有全部必要修复和再验证完成后才建议更新阶段状态

补算检查点审查需要覆盖父评估已经提交而派生子评估尚未完成时的进程中断，核对相同运行身份重复处理后派生结果继续传播、状态未重复累加且游标只越过完整窗口。已有历史补算最终仍会按 `finishReplay` 修订正式状态，第三阶段独立分析运行采用另外的结果保存范围。

现有用户修改需要保留，原有持久容器和卷保持原用途。必要依赖与镜像传输已经授权，临时数据与凭据使用独立目录和权限控制；报告输出省略凭据。工作卷至少预留 1 GiB，测试数据库使用唯一 schema。用户排除的完整 UOS 安装恢复、连续断云 24 小时、受限链路专项与实际 24 小时容量测量不纳入本轮审查。

存储专家最终普通全量中的 20 项条件跳过需逐项核对：14 项 PostgreSQL 用例已有 `storage-postgres-final.jsonl` 专项，计划并发用例已有规则专家 PG18 证据，受控16至18迁移夹具有独立导出恢复及目标读写记录；`TestTaskCrashProcess` 是由父测试调用的子进程入口。三节点协调由消息基础设施专家使用目标 NATS 版本验证，原生平台用例与第一阶段实际证据及最终集成范围对应；组织插件实际进程用例需要使用本轮构建的 `sf-hr-plugin` 设置 `SF_HR_PLUGIN_BINARY` 后补验。对当前代码需要再执行的用例明确安排，条件跳过本身保留原始结果。
