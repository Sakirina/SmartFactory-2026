发布界面工程师任务说明

本任务负责 E5-05，以及 E5-01 至 E5-04 的发布、配置、节点和运行状态页面。使用发布协调与节点身份工程师提供的契约，沿用第四阶段已经形成的业务模块、生成客户端、TanStack Query 和增量订阅；后端负责版本、权限和状态转换，页面负责让用户完成实际发布与处理流程。

用户能够选择程序、规则、配置及模板实例，查看依赖、内容摘要、兼容条件和受影响节点，再创建具有明确目标与批次的发布。页面显示每个节点的期望版本、准备结果、应用结果、实际运行版本及时间，用户可以辨认等待离线节点、应用失败、后续批次停止和需要人工操作的情况。允许的继续、取消、恢复与退回操作由服务端状态和权限决定，提交时使用当前对象版本并保存理由。

模板演进页面保留原始实例和设备绑定，展示新旧版本差异、可升级对象、冲突及待处理参数，用户能够对已通过检查的实例批量生成发布。配置页面呈现对应程序和节点、静态或动态生效方式及实际应用状态；凭据内容显示引用和访问状态，页面及导出省略明文。节点详情展示已验证身份、能力、实例与报告状态，并能查看其关联发布及失败原因。

验证流程如下：

1. 使用实际隔离节点创建包含程序、规则和配置的发布，在浏览器完成目标选择、依赖检查、批次创建与状态查看
2. 注入离线、版本冲突、应用失败和权限变化，完成合法恢复或退回并核对持久状态、审计和实际运行信息
3. 对五类模板中的实际实例完成版本演进，检查绑定保留、参数变化、冲突对象及批量发布结果
4. 核对云端和现场入口的节点、配置及发布显示，运行类型检查、前端回归和生产构建，保存截图、请求和数据库交叉检查
5. 形成 `.local/evolution/release-interface-verified.json`，交给构建交付及独立验收工程师，明确实际受测程序、规则、配置和前端摘要

文件归属为 `Frontends`、前端专项测试与公开操作说明；后端缺陷交给对应工程师，涉及生成契约更新先协调。浏览器验证使用独立会话、临时凭据和本轮测试发布对象。

实际运行报告的显示依据 `release-frontend-contract.md`：代理联系时间 `last_seen_ms` 与实际进程报告时间 `last_report_ms` 分别呈现，`report_age_ms` 与 `report_fresh` 按十五秒期限说明最近报告是否仍有效。历史批次保留其完成记录；代理持续查询但实际子进程停止时，页面显示报告过期和当前失败原因，并在程序恢复后刷新实际状态。普通心跳和相同报告保持人工操作版本，浏览器检查包含读取后经过正常报告仍可提交、业务变化后处理409两种情况。

节点配置前端夹具已登记在 `/private/tmp/smartfactory-phase5-node-frontend-live-20261005/frontend.json`，包含独立cloud、config、两个Edge及两个实际配置消费者。私有登录文件和运行PID文件只通过该记录中的路径读取，验证证据保存身份及结果而省略凭据值。发布专家另行提供包含实际程序切换和批次的 `frontend-fixture.json`，两个夹具各自的进程、数据库及受测摘要分别保存。
