第二阶段前端基础工程师任务说明

本任务负责 E2-12 的前端工具链迁移，以及 E2-09 的连续模拟和后台任务详情页面。规则工程师提供模拟、节点元数据及计划诊断接口，存储工程师提供任务详情及允许操作；前端工程师负责将这些接口用于实际页面，发现后端问题交给对应负责人处理。主协调者负责跨角色接口协调和验收。

实施前读取 [验收清单](acceptance.json)、`rules-frontend-contract.md`、`tasks-frontend-contract.md` 和 `Frontends` 当前结构；接口说明尚未形成时可以先完成工具链迁移。第一阶段已生成 `contracts/1.0/api-types.ts`，`src/generated-client.ts` 已用于草稿保存、校验和发布，`tests/generated-client.test.mjs` 覆盖精确整数、授权、版本及错误状态，后续调整需要保留这些行为。

工具链目标是 Node.js 24 LTS、Vite 8.1 及 TypeScript 6 至 7 的兼容迁移。先查询正式发行与兼容说明，锁定实际使用的版本；CLI 类型检查与生成工具所需编译器 API 分别使用受支持的入口。当前生成客户端测试依赖 `typescript.transpileModule`，需要核对所选包是否仍提供该接口。模块依赖、锁文件、构建脚本、CI 与工具链清单中对应记录保持一致，涉及共享构建或部署文件时先协调。记录实际执行的 node、npm、构建器和编译器版本，运行类型检查和生产构建。

整体方案中的 `openapi-typescript` 也需要完成实际组件验证：第一阶段为草稿流程提供了基于 OpenAPI 的 Go 类型输出器，本阶段使用正式 `openapi-typescript` 处理当前 OpenAPI 3.1 并用于生成客户端及新增页面，核对组合Schema、可选字段、参数、响应状态和精确数值映射。类型检查器与该生成器的编译器API依赖分别选版，避免产生两份彼此不一致的手工契约；如生成资源或 Go 导出器需要调整，先与存储工程师约定单一写入者和生成次序。报告包含所选组件及其替换范围、重复生成一致性和客户端回归。

连续模拟页面应提供有明确时序的多条输入、所选草稿修订及需要的模拟参数，展示每条输入的计算结果、节点解释、最终状态和复现所需的计划与输入身份。用户能够区分自行提供的历史与服务取得的历史快照；草稿修改造成版本冲突时，页面保留当前编辑内容并说明需要重新校验的对象。数值输入、响应解析、显示和导出沿用现有精确整数处理，单位、质量和时间来源应在相关显示中保留。

后台任务页面应展示当前任务的业务身份、状态、尝试次数、下一次执行时间、失败原因与进度，只提供服务端当前状态和用户权限允许的操作。取消或重试时使用明确任务版本，处理处理中状态与冲突，操作完成后更新相应查询。任务资源授权和允许操作由后端判断，前端需要显示服务返回的实际结果。

本任务的文件归属为 `Frontends`、对应前端测试与操作说明。后端生成契约由负责接口的工程师维护，生成类型变化后更新调用处；TanStack Query 的全面页面迁移、参数表单和 ECharts 6 的业务页改造属于第四阶段，当前需要的新页面结构应便于后续衔接。

验证流程如下：

1. 核对锁文件与实际工具版本，执行现有精度和生成客户端测试、类型检查及生产构建，确认云端、现场和大屏三个入口均可加载
2. 启动隔离的当前后端和前端构建，用浏览器完成连续输入模拟、结果与状态查看、过期草稿修订处理，并核对数据库业务状态未被模拟修改
3. 使用包含失败与重试状态的后台任务完成详情展示和允许操作流程，验证无权限与过期版本响应，核对服务端任务结果
4. 保存浏览器截图、关键请求断言、控制台结果、命令日志和产物摘要，生成 `.local/evolution/frontend-phase2-verified.json`，逐项说明对应 E2-09 和 E2-12 的验证范围

Node.js 24.21.0 已位于 `.local/toolchains/node-v24.21.0-darwin-arm64/bin`，必要依赖与镜像传输已经授权。缓存、构建或临时数据库优先使用 `/private/tmp`，工作卷至少保留 1 GiB；浏览器使用独立会话与临时凭据，测试报告省略认证内容。现有用户修改和原持久服务保持原用途。

第一阶段已验证 Playwright CLI 可以使用本机 Chrome；该轮浏览器会话与 18990 应用已结束。新会话使用自己的 `-s=<name>` 名称，`PWTEST_DAEMON_SESSION_DIR` 和 `npm_config_cache` 指向本轮 `/private/tmp` 子目录。旧文档中的 `--session name` 在本机包装器曾返回空输出，已用 `-s=name` 完成实际操作；浏览器请求命令为 `requests`。先按当前 Playwright Skill 读取使用方式，再创建独立会话与服务。
