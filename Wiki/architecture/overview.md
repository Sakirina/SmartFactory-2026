# 系统架构

[Wiki 首页](../README.md) · [配置参考](../reference/configuration.md)

SmartFactory 由采集、业务和原生平台共同运行。DataTransfer 面向协议设备，边缘业务服务保存现场数据、计算和控制，云端汇集业务并维护人员、规则及发布，配置中心按程序身份提供参数与连接器固定内容。

| 组件 | 主要职责 |
| --- | --- |
| DataTransfer | 协议读取、统一消息、缓冲与确认、动作日志和命令结果 |
| sf-edge | 设备准入、现场观测、正式规则、控制、离线许可与同步 |
| sf-cloud | 全厂查询、正式定义、人员、业务处置、工件及批次协调 |
| sf-config | 独立配置数据库、密钥、身份校验、固定配置分发 |
| sf-release-agent | 核验目标、工件及配置，管理实际 Edge 子进程和报告 |
| ThingsBoard CE／Edge | 原生实体、遥测、规则链和告警投影 |
| PostgreSQL | 持久业务、配置和原生数据库 |
| Kafka | 原生平台消息服务 |
| NATS JetStream | 多节点执行权及签名检查点 |
| Envoy | 浏览器 HTTPS 与业务转发 |
| Frontends | 云端、现场及大屏，类型化查询与操作页面 |

## 观测和计算

设备消息经 DataTransfer 转成统一字段，业务桥检查批准状态、节点及配置版本，再将观测与相应投递记录持久保存。正式定义在发布时编译计划，计算核读取选择器、有效历史和状态，形成分析输出、告警或预案意图；实时现场控制完成条件、命令与回执流程。

原始观测保留质量、来源及精确值，较早内容按策略归档，热表和归档共同供查询。迟到观测进入历史补算，采用当时规则与资产版本，保存修订；回放、比较和影子计算固定输入快照并保留逐点解释。

## 应用、事务和后台任务

应用服务统一处理身份、资源、业务版本及动作条件。重要业务更新把对象、审计和待投递事项按对应事务保存，投递及同步在提交后继续处理；查询读模型按提交游标提供窗口与分页。

PostgreSQL 部署采用 Goose 编号迁移和 River 后台任务，SQLite 用于开发与限定场景。任务保存原业务身份、阶段、游标和恢复记录，重试继续已有检查点，取消处理后续计算；数据库升级与恢复步骤见[运维指南](../operations/backup-restore.md)。

## 云边和现场运行

云边业务通过 mTLS 认证节点，按稳定消息身份、确认和游标交换观测、定义、权限、审计与执行资料；原生 CE／Edge 使用相应 TLS 转发通道。现场签名权限包有独立有效期，配置和发布缓存按其固定内容及认证检查继续采用。

多节点预案使用 NATS 三副本 KV 保存执行权、代次和签名检查点，节点检查规则版本与摘要。法定多数、参与者或时效失效时采用已配置本地降级步骤，恢复时核对实际设备效果、原命令和检查点。

## 固定发布和工具调用

发布将程序、规则、参数和连接器组成不可变清单，声明平台及数据库等兼容条件。代理准备核验后切换进程，保留原数据库和主密钥，协调器按有效运行报告推进批次，失败恢复沿同一任务和经过授权的新代次进行。

AI 和 MCP 使用相同应用许可，调查保存实际进入模型的 JSON 依据和来源版本。前端生成客户端由公开契约生成，数据、告警和执行采用服务端分页与可恢复订阅；具体接口见[API](../api/rest.md)，发布操作见[节点指南](../user-guide/node-releases.md)。
