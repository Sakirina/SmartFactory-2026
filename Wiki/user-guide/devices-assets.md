# 设备、资产与协议参数

[Wiki 首页](../README.md) · [DataTransfer 接入](../integration/data-transfer.md)

设备是采集与控制对象，资产组织工厂、车间等逻辑层级，边缘节点表示设备所属的现场服务。统一设备标识、资产归属、准入和版本会共同参与观测检查、资源授权及模板绑定。

| 对象 | 主要信息 |
| --- | --- |
| `asset` | 名称、上级 `parent_id`、状态和版本 |
| `device` | 统一标识、所属资产、`edge_id`、协议、采样周期和配置 |
| `edge` | 现场节点标识、资产归属与登记信息 |

DataTransfer 的 `device_id` 与业务设备标识保持一致，业务桥核对已批准状态和所属节点后保存观测。授权到某个资产时，权限检查沿其层级查询下属资源。

## 发现并批准现场设备

1. 准备设备协议、测点和动作映射，启动所属节点的采集连接器；配置步骤见[接入指南](../integration/data-transfer.md)。
2. 在该节点现场工作台进入“设备与资产”，查找发现的设备，或选择“登记设备或资产”；核对标识、名称、所属资产、协议、采样周期及配置。
3. 使用具有登记权限的账号将设备设为 `approved` 并保存，系统保存新设备版本并投递采集配置。
4. 进入“数据监控”确认同一标识的观测、时间、质量及来源，再核对“协议与设备参数”中的采用回执。

物理设备批准在所属边缘服务完成，云端展示同步后的设备资料。设备仍处于候选状态、标识不符或属于其他节点时，业务桥保留相应原因供排查。

## 维护协议和连接器

“协议与设备参数”提供设备基础参数及正式连接器配置。参数表单读取协议目录，展示连接、采样、数据点与动作字段；“完整参数与扩展”允许检查额外字段，保存时保留原 JSON 值类型及未修改的扩展。

1. 选择设备或连接器，阅读当前协议、节点、已阅版本及允许操作，再打开编辑窗口。
2. 填写现场地址、通信参数、测点及动作映射，点击“配置预检”，按字段错误修正。
3. 保存后核对配置版本和下发回执，区分保存完成、等待投递和实际采用。
4. 出现版本冲突时，使用“采用更新后的保存依据，保留已填写参数”，阅读新版本后再提交。

连接器凭据使用配置中心的密钥引用，公开配置和页面详情保存引用身份。程序采用结果继续从实际 DataTransfer 消费者读取，固定发布的配置与采用记录见[节点配置指南](node-releases.md)。

## 资产变更和版本

云端逻辑资产更新保存正式版本；现场逻辑资产更新生成变更申请，云端具有权限的人员在“现场资产变更申请”阅读原版本、内容与申请节点，填写意见并批准或拒绝，随后同步正式对象。

首次创建使用 `expected_version: 0`，已有对象更新使用上次读取的版本。并发修改返回 HTTP 409，页面保留输入供人员核对；设备配置版本通过 `entity_revision` 进入采集和观测，资产历史版本供历史计算采用。
