# 节点配置与分批发布

[Wiki 首页](../README.md) · [配置参考](../reference/configuration.md) · [备份与恢复](../operations/backup-restore.md)

节点程序以登记的工作负载身份取得允许配置，固定发布组合同时指定程序、规则和参数／连接器版本。协调器按批次下达目标，代理核验工件与配置、切换实际进程，并上报当前采用内容。

## 身份与配置阶段

工作负载登记固定节点、程序、用途、能力、参数和连接器范围；普通程序与发布代理使用独立凭据。准备入口生成初始登记和令牌文件，后续启动读取已经维护的停用、授权与凭据代次；“节点身份与配置”提供当前范围和轮换操作。

| 阶段 | 含义和检查对象 |
| --- | --- |
| `desired` | 本次目标的固定版本与摘要 |
| `prepared` | 当前程序已取得并核验内容 |
| `applied` | 配置已提交实际消费者 |
| `running` | 运行策略或 DataTransfer 确认实际采用内容 |
| `restart_required` | 静态参数已经准备，等待新进程采用 |
| `failed` | 授权、核验、应用或消费者检查失败，保存原因 |

密钥使用引用身份，所属 Edge 解析私有载荷；公开详情保留引用与代次。动态应用失败时恢复此前有效值，静态配置在新进程启动后采用，连接器报告核对 MQTT、Modbus TCP 或 OPC UA 的实际消费者。

1. 维护身份时先核对节点与程序，再调整能力和资源范围。
2. 轮换凭据后将新凭据保存到该身份的私有令牌文件，并确认进程使用新的代次。
3. 查看期望、准备、应用、运行的固定版本与摘要，静态待重启和实际失败分别处理。

普通配置订阅暂时遇到网络或权威服务故障时，启动读取已有、经过校验的本地运行配置；明确的 HTTP 401／403 或身份变化事件会清除该身份管理的配置缓存，恢复后按当前授权重新取得内容。

## 首份固定发布

发布目录可以从空目录开始，前提是已经存在可登记程序工件、正式规则及配置。

1. 完成[实例安装](../installation.md)，保持原 Edge 在线，在包根目录登记程序：

   ```sh
   python3 scripts/register-release-artifact.py \
     --bundle "$PWD" \
     --directory ../smartfactory-state
   ```

   工具默认核对 `bin/sf-edge -build-info`、文件摘要、包版本和源码摘要，使用客户 CA 上传二进制并登记构建信息。初始管理员密码已修改时加 `--password-file`，其他账号加 `--login`，其许可需满足发布管理条件。

2. 在“云边发布”核对工件版本、Linux／amd64、数据库范围、规则与配置格式及摘要；工件大小为 1 字节至 256 MiB。
3. 打开“组合固定发布”，填写新身份和名称，选择程序、规则及参数／连接器版本。规则与配置各至少一项，检查摘要、依赖和适用节点。
4. 使用“检查组合”，修正服务返回的问题后保存不可变发布。已有组合可作为编辑参考，每次保存采用新的发布身份。
5. 创建批次部署，按工作负载身份安排先后批次，例如 `release-edge-a`，填写理由并提交。

云端工件保存在私有 `release-artifacts/`，数据库保存固定组合、分配与报告。账号可访问的详情与目录管理许可分别校验，受拒绝的操作显示具体原因。

## 将原 Edge 转换为代理管理

1. 保持原 Edge 及其连接器密钥源在线，准备当前已分配发布：

   ```sh
   python3 scripts/bootstrap-runtime.py prepare-release \
     --directory ../smartfactory-state \
     --nodes edge-a
   ```

   入口调用代理的 `--prepare-only`，完成身份、分配、工件及固定配置核验，保存加密缓存后退出。

2. 核对当前批次再启用：

   ```sh
   python3 scripts/bootstrap-runtime.py enable-release \
     --directory ../smartfactory-state \
     --nodes edge-a
   ```

   工具再次准备当前目标，停止原 Edge，将依赖改为代理并保存 `release_managed_nodes`，使用同一数据库、主密钥、监听与原集成设置启动子进程。

3. 阅读节点报告，核对发布、程序、规则、配置摘要，实际 PID、进程实例、应用和数据库版本。协调器在本批目标都取得有效运行报告后推进后续批次。
4. 后续节点进入当前批次后逐个执行相同转换，正常启停使用同一私有目录的 `bootstrap-runtime.py`。
5. 直接查看 Compose 时包含发布 profile：

   ```sh
   docker compose -f ../smartfactory-state/compose.json \
     --profile native-edge --profile release ps
   ```

## 离线、失败和逐批恢复

节点查询时间和实际运行报告时间分别显示，默认运行报告十五秒后过期；历史完成记录保存，当前批次推进检查有效的现行实例报告。离线节点等待，失败节点阻止后续批次，详情的 `allowed_actions` 决定暂停、恢复、重试或取消条件。

1. 保留失败组件、任务、代次及摘要，核对程序、规则、配置、身份和实际消费者。
2. 修正外部条件，读取当前业务版本并提交允许动作；冲突时使用“核对状态并更新操作依据”，保留已填写理由。
3. 核对当前批所有目标达到 `running`，再继续后续批次；恢复通信后再次取得当前身份和分配。
4. 实际缓存程序启动失败时，通过新登记的工件和正式目标恢复，或显式重试形成新代次。

已确认运行发布在 cloud／config 暂时不可达时，可从所属节点的加密缓存启动：主密钥、缓存认证、固定清单、全部引用及工件摘要通过检查，已有进程身份也须与持久记录一致。首次发布仅有待完成缓存、尚无确认运行程序时，代理等待在线权威继续采用目标。

密钥源暂时不可用时，代理只复用当前、已运行或待完成缓存中完全相同的固定载荷，逐项检查节点、程序、用途、正文、引用及凭据代次，并在线核验当前身份、实例和解析能力。明确授权拒绝或内容冲突使该复用检查失败。

核验成功后的实际启动失败保存在 `restore-status.json`，同一部署、代次和发布持续等待经过授权的新目标或重试，代理重启后保留该状态。缓存认证、工件摘要或已有进程身份失败则返回对应核验错误。

## 旧内容再次采用与模板演进

退回旧发布先核对旧程序的数据库兼容范围。兼容时规则固定来源与节点本地应用版本分别记录，连接器固定来源与运行代次也分别保存，人员可检查实际往返后的内容；超出兼容范围时，按[备份与恢复](../operations/backup-restore.md)停止写入、保存当前状态并恢复配套备份到独立目标，再核对备份之后的数据和设备动作。

固定载荷初始化只采用该发布列出的配置，已经移除的参数继续保持缺失；本地变更版本递增，来源固定版本保持可追溯。“场景模板”的版本演进沿原批次和实例生成新组合，保存设备、连接器和参数绑定、影响及采用记录，再按上述批次流程部署。
