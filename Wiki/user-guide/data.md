# 数据监控与历史补算

[Wiki 首页](../README.md) · [数据契约](../api/data-contract.md)

“数据监控”按设备、测点、固定时间范围和粒度查询已提交观测，页面同时保存精确值、单位、质量、来源及修订。查询由服务端筛选分页，首屏可以订阅变化，完整导出沿同一快照读取后续页。

## 查询与导出

1. 选择设备和测点，多个字段使用英文逗号分隔；选择最近一小时、24 小时、30 天或三年，以及原始、分钟、小时或日粒度。
2. 点击“查询历史”，核对页面显示的起止时间和订阅状态，阅读趋势和“精确观测记录”。
3. 使用上一页、下一页查看相同查询的续页；要更新当前时间范围，再次执行查询。
4. 点击“导出完整精确数据”，保存包含全部页的 JSON。导出过程中出现错误时，处理原因后重新导出。

趋势按设备、测点和单位组织系列，工具提示、表格与导出保留 JSON 原值；绘图坐标在显示阶段使用数值近似。布尔状态采用阶梯展示，文本和复合值在相应详情中阅读，界面时间使用 `Asia/Shanghai`。

## 质量、缺口与来源

| 字段或标记 | 阅读方式 |
| --- | --- |
| `GOOD` | 有效观测，默认参与业务计算 |
| `BAD`、`UNCERTAIN` | 无效或不确定质量，结合质量原因查看通信和设备 |
| `quality_scope` | `page` 表示有效、无效及不确定数量采用当前页 |
| `gaps` | 已记录缺口的设备、测点、起止时间、缺失数量和原因 |
| `completeness` | `complete`、`incomplete` 或 `unknown`，按固定查询范围解释 |
| `sources` | 最近通信、来源状态及补传进度 |
| `revisions` | 前后值、原因、任务和结果版本 |

温度达到工艺告警阈值时，观测质量仍可为 `GOOD`，告警由正式规则判断。来源离线、质量无效、缺失和等待补传各自描述对应条件，可以一起用于检查这一时间段。

## 存储、补传与修订

默认原始观测保留 30 天，分钟汇总 90 天、小时汇总 365 天、日汇总及告警 1095 天。归档默认将最近 24 小时保留在热表，较早完整观测按块保存；同一查询入口读取热表与归档，具体策略由[配置中心](../reference/configuration.md)调整。

延迟观测在默认 30 天范围内触发自动历史处理，计算采用当时的规则和资产版本，修订保存原值、新值、原因及任务。超出自动范围的观测进入待人工检查的暂存流程，可以结合缺口和业务需要安排补算。

1. 在“历史补算”选择“创建补算任务”，填写设备、起止时间和原因。
2. 查看任务阶段、进度与失败信息，打开关联后台任务核对游标、已提交结果和允许操作。
3. 完成逐点处理后继续检查汇总阶段与队列完成状态，再查看“来源与数据修订”中的实际变化。

历史补算采用分析和告警计算路径，设备动作通过实时策略与[控制流程](control.md)处理。任务取消、重试与历史回放见[历史分析和后台任务](history-tasks.md)，程序对接的续页和可恢复订阅见[HTTP API](../api/rest.md)。
