# 分析、告警与联动编排

[Wiki 首页](../README.md) · [连续模拟与历史分析](history-tasks.md)

定义保存输入选择器、节点、连接、输出与业务政策，发布时完成校验和编译，形成后续计算采用的正式版本。草稿修订、正式规则版本和发布采用记录各自保存身份，便于多人编辑、评审及历史追踪。

| 页面 | `kind` | 主要结果 |
| --- | --- | --- |
| 数据分析 | `analysis` | 聚合、表达式或计数的持久输出 |
| 告警编排 | `alarm` | 异常与恢复判断、告警级别和通知 |
| 联动预案 | `strategy` | 现场条件、风险、设备步骤与降级处理 |

## 编辑、检查和采用

1. 使用拥有草稿许可的账号创建定义，或打开已有定义的“编辑与评审”，填写名称、设备及测点，核对自动生成的定义标识和默认窗口。
2. 从“可用节点”添加节点，连接输入与输出端口，点击节点编辑参数并应用。表单展示正式节点目录中的类型、必填、枚举、范围和单位。
3. 需要检查输出、依赖、端口或预案政策时，打开完整定义 JSON 并应用修改，保持节点标识及引用对应。
4. 保存草稿后点击“校验”，处理节点、类型、表达式、依赖与循环问题；每份定义支持 1 至 128 个节点、最多 512 条连接。
5. 执行[连续模拟](history-tasks.md)，核对实际草稿修订、输入和逐点解释，再打开评审窗口阅读语义差异与影响分析。
6. 由具有发布许可的人员确认采用，系统保存新的正式版本、生效时间与编译计划；已经开始的执行继续采用其创建时固定的预案版本。

节点目录通过 `GET /api/sf/v1/rule-nodes` 提供，运行、校验和表单采用同一元数据。窗口聚合使用有效数值，阈值与回差保留运算符的包含关系，延时节点按逻辑时刻推进状态，事件计数采用稳定事件身份。

## 语义评审与影响

评审按节点、连接、参数、端口、输出、控制政策和引用展示变化，影响分析检查依赖、资源访问和计算预算，并返回本次分析是否完整。改变编辑内容后重新执行比较，以本次草稿修订和正式基准作为发布依据。

发布流程同时检查角色、资源和版本，正式定义与审计、后续任务采用相应事务处理。未提交的名称、画布与参数继续保存在当前编辑窗口，列表刷新后仍可核对；HTTP 409 时读取最新修订，保留输入并比较其他修改，再保存和评审。

## 输出、停用与历史恢复

分析输出指定字段、类型、单位及提供结果的节点，正式采用后进入数据目录，供数据页面、大屏、AI 与 MCP 查询。示例见[工厂定义](../../examples/factory/definitions.json)，具体阈值与动作见[五场景教程](../tutorials/five-scenes.md)。

停用更新定义状态。恢复历史内容时打开“版本记录”，选择历史版本并创建回滚草稿，草稿绑定当前正式基准；完成校验、模拟和差异评审后保存为新的正式版本。接口分别为 `GET /definitions/{id}/versions` 与 `POST /definitions/{id}/rollback`，路径均使用 `/api/sf/v1` 前缀。

固定发布再次采用旧规则时，来源固定版本、内容摘要和节点本地应用版本分别记录，追踪方法见[节点配置与分批发布](node-releases.md)。
